# 连接地址与自动隧道

## 地址选择

1. `pairingOrigin` 非空时使用保存的 HTTP(S) origin，不启动隧道。管理员负责该地址可从手机访问。
2. `pairingOrigin` 为空时自动启动公网隧道。配置字段保持空字符串，实际 HTTPS origin 单独保存，不把临时地址变成手动配置。
3. 新二维码始终包含实际地址；入口未就绪时不生成二维码，不接受配对和受保护设备请求，状态检查仍可用。

## 隧道实现

采用 [Cloudflare Quick Tunnel](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)，无需 Cloudflare 账号或自有域名。插件启动官方 cloudflared 客户端，为本机设备接口申请临时 `https://*.trycloudflare.com` 地址。

首次使用从 Cloudflare 官方 GitHub Releases 下载固定版本 cloudflared 2026.11.0，按该版本发布的 SHA-256 校验，缓存在当前 DSH profile 的数据目录。再次使用缓存也校验。下载、校验、平台兼容、申请地址、进程启动或运行失败均明确显示；不忽略错误、不关闭 TLS 校验、不切换其他服务。

插件另开只监听 `127.0.0.1` 的临时 HTTP 端口，复用 VoxChat 设备处理器。cloudflared 只连接此端口，未知路径返回 404，不转发 DSH 网页、Remote、设置和其他插件接口。音频上传和 NDJSON 响应直接流式处理。DSH 无需修改本机监听或路由器设置。

隧道依赖 Cloudflare，音频及会话响应经过该服务。Quick Tunnel 新建时通常会改变地址，不提供可用性保证，适用于临时访问。VoxChat 使用 NDJSON 流传输。Windows x64、Linux x64/ARM64 自动下载客户端，其他平台明确提示使用手动地址。停用插件、切换手动地址或正常退出时关闭进程与临时端口。失败后管理页可手动重试；cloudflared 自身的同地址网络重连不触发重新配对。

## 地址变化与设备下线

SQLite 单独保存最后一次生效的 origin。新地址规范化后与它比较：

- 相同：保留凭证和配对码，包括手动地址重启以及隧道返回同一地址。
- 不同：事务中更新地址并清空全部设备的 `token_hash`、`paired`、`pairing_hash`、`expires`，增加配置版本；提交后取消语音任务、终止活动设备 HTTP 请求。
- 失败或尚未获得地址：不把空地址记为一次有效变更，不接受配对或受保护请求；恢复后继续与最后有效地址比较。
- 首次记录地址：将实际生效地址保存为后续比较的基线。

保留设备 ID、名称、工作区授权、当前工作区、各工作区会话选择、模型配置、音色选择及请求去重记录。不创建新设备、不删除会话、不自动签发或延长配对码。

用户在原设备卡片手动刷新配对码后重新绑定，获得新 token；旧 token 永久失效。配对码仍为 6 位字母数字、5 分钟有效、一次使用。

## 管理页面和接口

输入框提示「留空自动启动公网隧道」。「DSH 访问地址」旁的提示图标通过鼠标悬停或键盘聚焦展示连接规则，不再在输入框下常驻说明。展示保存后的连接方式、状态和实际地址，失败展示原因与「重试隧道」。运行地址不写进配置草稿。

管理视图包含 `connection`：`{mode: "manual" | "tunnel", status: "starting" | "ready" | "error" | "stopped", origin: string | null, error: string | null}`。`configurePairing` 保存后应用模式；隧道异步启动，保存成功不代表连接就绪。`retryTunnel` 仅在自动模式失败后可用。

页面自动更新运行状态，不覆盖未保存表单；地址变化更新版本，有草稿时提示重新载入并立即隐藏旧二维码。设备协议为 v2，不实现客户端静默更新地址或自动找回，连接失效后用户重新配对。

## 验收

- 手动地址不下载或启动隧道；留空自动启动。
- 真实公网入口支持状态检查、配对、录音上传和 NDJSON 分段接收；其他路径不能访问 DSH。
- 同地址重启保留 token；换地址使全部旧 token、配对码失效，活动请求结束，设备数据保留。
- 错误可见且可重试；模式切换、重复启动、启动中卸载不残留进程或旧入口。
- 离线测试不连接公网；公网验证使用隔离数据。
