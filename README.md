# VoxChat

通过 iOS、Android 等客户端，用语音与 DeepSeek Harness（DSH）会话交流。

插件接收录音，经 ASR 转写后发送到 DSH；保留完整回复，再生成适合播报的摘要，经 TTS 转为音频流返回客户端。本仓库包含 DSH 插件和管理设置页，手机客户端由独立项目实现。

## 功能

- 以设备为入口管理配对和工作区授权，设备与工作区支持多对多关联。
- 6 位字母数字配对码，5 分钟有效、一次使用、手动刷新；二维码支持点击放大。
- 设备可浏览已授权工作区的历史会话，切换工作区和会话。
- ASR、TTS、总结模型均支持 OpenAI 兼容接口，设备配置优先于插件配置；总结还可继承当前 DSH 会话模型。
- 统一管理音色，设备选择音色；插件保存选择并向设备返回当前音色和完整音色列表。
- 返回转写、可见会话过程、完整回复、播报稿及音频流，摘要不会替换 DSH 原文。
- 支持手动访问地址和自动 Cloudflare Quick Tunnel。

## 安装

需要 Node.js 22.13+ 和 DSH Web profile。宿主集成已验证 DSH `0.2.1-rc.2`。

```powershell
npm ci --ignore-scripts
npm test
npm pack
dsh plugin --profile web add ./fevolq-voxchat-0.1.0.tgz --ignore-scripts
```

`web` 替换为实际 profile。安装后刷新 DSH 页面，在「设置 → 语音交互」中配置。更新涉及后端代码时，需要在插件详情中停用并重新启用，再刷新页面。自动隧道重建可能改变地址，触发设备重新配对。

安装包由源码构建，包含管理页所需的二维码库，无额外 npm 运行依赖。`private: true` 用于防止误发布到 npm，不影响 Git 仓库提交或本地安装。

## 配置与使用

1. 添加设备并保存，客户端输入配对码或扫描二维码完成绑定。
2. 在设备卡片中为设备选择可用的 DSH 工作区。
3. 完成插件级 ASR、TTS 配置，选择总结模型的配置方式。
4. 在音色管理中添加音色名称及 TTS 服务要求的音色 ID。
5. 客户端选择音色、工作区和会话，提交录音并播放返回的音频流。

新安装时服务地址、密钥、模型和音色库为空，不预置个人配置。新增、移除、工作区授权和模型编辑先进入草稿，点击「保存配置」后统一生效。

### 模型

| 能力 | 配置优先级 | 请求接口 |
| --- | --- | --- |
| ASR | 设备 → 插件 | `POST /audio/transcriptions`，multipart 音频上传 |
| TTS | 设备 → 插件 | `POST /audio/speech`，二进制音频流 |
| 总结 | 设备 → 插件 → 当前会话 | 独立配置使用 `POST /chat/completions`；继承会话时使用 DSH 模型适配器 |

独立配置需填写基础地址和模型名，例如 `https://example.com/v1`；插件会在地址后追加对应接口路径。API Key 在无需认证的服务上可留空。ASR 可指定识别语言，TTS 可指定语速和音频格式。

插件级 ASR、TTS 必须配置，设备可按能力覆盖。总结是语音流程的必要步骤，继承当前会话模型是一种有效配置。音色在客户端选择，插件配置页只管理音色库。

配置按整项能力覆盖，不混用不同服务的密钥。管理页只返回密钥是否已保存；编辑同一服务地址时省略密钥会保留原值，更换地址不会自动复用原密钥。

### 连接与配对

「DSH 访问地址」填写手机可访问的 HTTP(S) origin 时使用该地址；留空则自动启动 Cloudflare Quick Tunnel，取得临时公网地址。插件自动下载并校验官方 `cloudflared`，通过子进程管理隧道，无需手动安装服务或注册 Cloudflare 账号。

二维码只携带连接地址和一次性配对码，由插件本地生成。配对码原文只在签发时返回，重新打开页面后可手动刷新；到期、刷新页面或重启都不会自动续期。

实际连接地址变化会使全部设备下线、旧凭证和配对码失效，设备配置与工作区授权保留。用户在原设备卡片刷新配对码后重新绑定。同地址重启保留凭证。

隧道只转发 VoxChat 设备接口，音频和会话响应经过 Cloudflare。平台支持、生命周期和故障处理见 [连接说明](docs/connection.md)。

## 数据与运行规则

- 插件配置、密钥、音色、设备授权和请求去重信息保存在 `<profile>/data/voxchat.sqlite`；设备接口不返回模型配置或密钥。
- DSH 保留会话原文。插件不持久化录音或生成音频，不提供音频重放或断线续传。
- 每台设备独立选择工作区，每个设备与工作区的关联独立记住会话；请求开始后固定工作区、会话、模型和音色。
- 同一设备、同一会话同时只接受一轮请求，不隐式排队。响应仅发送给发起设备。
- 断线、取消、撤销设备、解除本轮工作区授权或卸载插件会停止请求，已经写入 DSH 的内容不回滚。
- DSH 原有权限和审批机制保持生效；需要审批或工具交互时，在 DSH 中处理。
- 客户端通过一次 `POST /turns` 持续读取 NDJSON 响应，无需轮询。`complete` 表示服务端交付音频完成，播放由客户端负责。
- 跨设备连接应使用 HTTPS，保护配对码、凭证和录音。

## 开发与验证

```powershell
npm run build
npm run check
npm test
```

默认测试使用临时数据库和本地模型服务，覆盖配对、授权隔离、语音流程、错误与取消、设置页和重启后的数据恢复。测试替身仅存在于 `tests/`。

使用已安装的 DSH 运行真实宿主集成测试：

```powershell
$env:DSH_TEST_PACKAGE = Join-Path (npm root -g) '@deepseek-ai/dsh/package.json'
npm test
```

也可将 `DSH_TEST_PACKAGE` 指向其他安装位置的 `package.json`。未配置时，宿主集成测试会明确跳过。集成测试使用隔离 profile，不修改正在使用的 DSH 配置；不调用付费模型或公网隧道。真实手机端和模型服务的端到端联调需在对应环境完成。
